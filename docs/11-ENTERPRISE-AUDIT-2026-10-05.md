### SQL compatibility and offline remediation update

An isolated MariaDB 10.6 test database exposed required timestamp defaults incompatible with strict SQL mode and an assessment scoring lookup that selected answer primary keys instead of question IDs. Required no-default timestamps now use explicit date-time columns; grading uses question-keyed base collections and a deliberately mismatched-ID regression. The community dashboard used nonexistent event/message columns; it now counts published upcoming events and tenant-scoped unread messages. SQL validation now passes. These changes have not been migrated into production.

Seven storage regressions cover encryption, tab-key loss, account switching, logout, failed-send retries, revoked access, expiry and changed server sessions. Three additional service-worker regressions cover public-only caching, offline fallback, legacy cleanup and authenticated synchronization. Four backend tests cover lease tampering, owner/lesson binding, revoked/disabled/SCORM download guards, receipt replay and logout cleanup. Browser zoom restrictions were removed and mobile form clearance was corrected.

Historical SQLite data exposed one `premium` course type and a resource MIME value longer than the old ten-character schema. New migrations preserve the original course label in `legacy_commercial_type`, map known commercial labels to `self_paced` without changing prices, reject unknown classifications and support full resource MIME values. SQLite timestamps in SQL `DATE` columns are compared by date; every affected column/count is recorded, with the raw SQLite snapshot retained on the protected host. Migration tests also exposed and repaired index-drop ordering during rollback. See [the operations runbook](../ops/README.md) for deployment boundaries.


### Contact workflow and access-boundary continuation

The administrator CRM now imports UTF-8 CSV files up to 50 MB through a durable background queue, with no fixed contact-count cap. Default and per-row types include Lead, Prospect, Customer, Partner, Student and Alumni. Streaming validation, 100-record checkpoints, serialized duplicate checks, actor-bound receipts and retry protection preserve imported contacts without overwriting existing ones. The interface provides upload/processing progress, persistent history, cancellation, resume and a row-error report. Valid rows continue when other rows are invalid or duplicated. Import creates no learner accounts and sends no messages. Both contact forms include company, job title, source, WhatsApp and a structured address. Activity/deal field contracts and the contact activity feed were also corrected. The earlier small-file preview API remains for compatibility; the current UI uses the background workflow.

Additional regressions cover resource publication/private URLs, unscanned assets, catalog payload minimization, revoked AI conversation access and bearer SCORM links after organization deactivation. The prerequisite editor includes circular-dependency rejection and inherited rules for new course editions.
