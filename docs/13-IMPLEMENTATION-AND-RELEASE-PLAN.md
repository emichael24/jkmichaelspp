## Required end-to-end release journeys

1. **Platform author:** create draft → module → text/video/PDF lesson → assessment → preview → readiness failure → correction → independent approval → publish → revision → archive. Exercise saves, validation, refresh and concurrent edits.
2. **Facilitator:** create course → build curriculum → thumbnail → submit → changes requested → revise → resubmit → approval; manage a cohort, weekly plan, assignment, rubric, resubmission and gradebook. Attempt foreign child IDs.
3. **Learner:** register/verify → onboarding → purchase or enroll → drip/prerequisite gates → study → save/resume timed assessment → review → completion → certificate. Include suspended access and connection loss.
4. **SME:** inspect pending content → edit/request changes → separate author/reviewer approval → publish correct content type → version diff → question flag resolution → item statistics. Verify audit events.
5. **Organization admin:** onboard company → departments → users/import → seats/assignments → scoped progress/export → deactivate learner → check access revoked. Repeat with a second organization.
6. **Intern/sponsor:** enroll → task/evidence → submit → rubric feedback → resubmit/version history → approval → meeting/attendance → portfolio → completion credential. Try unrelated sponsor access.
7. **Finance/operator:** verified provider event → exactly-once fulfillment → repeated/delayed events → cancellation/refund → reconciled ledger/report; persistent settings, audit search, notification outage and backup restore.

## Migration and rollout notes for this batch

The initial batch added nullable `question_snapshot`, `draft_responses` and `expires_at` fields to assessment attempts. Apply it in staging before deploying controllers that read/write these columns. Back up and verify a restore before production migration. Existing completed attempt history is retained; legacy in-progress attempts lacking snapshots are explicitly abandoned on resume and must restart. Communicate this to learners before rollout.

Course enum values remain canonical. A forward migration now preserves known historical commercial labels in `legacy_commercial_type` and assigns `self_paced` delivery without changing prices; unknown labels abort. The SQL rehearsal verified one such legacy course. Resource MIME metadata is widened to 127 characters. Existing paid plans that used manual activation still require a business review; historical subscriptions are not silently revoked.

Service-worker v7 uses per-build public-asset caches and removes prior private caches. Saved reading material is encrypted and isolated by account/session/tab with a 24-hour lease. Reading-completion sync is authenticated and replay-safe; quizzes, SCORM and media stay online-only. Device/network-loss acceptance remains required. Dependencies and assets must be installed/built from the new lockfiles as a single deployment.

Roll back application code and assets together if necessary. Retain the nullable assessment columns and saved snapshots while rolling back code; dropping them destroys new attempt evidence. A database rollback must be a separately reviewed operation. No production migrations, provider transactions, messages, push, commit, remote push or deployment were performed by this audit batch.

## Completion rule

An item is complete only when its implementation, realistic successful journey, negative authorization/failure cases, operational dependencies and evidence are all present. A route, screenshot, database table or old report check mark alone is insufficient. The enterprise release decision remains **NO-GO** until the P0 gates and release-critical P1 journeys above pass.
